# User perspective

Use the user's requested perspective. Otherwise, audit Guidepost as a collector or player, including someone visiting for the first time.
Record the task, device context, experience level, and relevant constraints in the report. Ask only when missing information would
materially change the audit; no provider-specific persona file or separate setup workflow is required.

Explain findings through user impact: whether a person can find a tool, understand ownership versus coverage, complete a transfer,
recover from an error, or return to their work. Do not dismiss accessibility problems because the assumed user does not need an aid.

If several perspectives are in scope, label their scenarios and results in the same report. Separate reports are optional when useful.
Revisit affected scenarios if assumptions change; do not present one perspective's observations as evidence for another untested flow.
