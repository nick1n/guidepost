# Progress during long audits

Record findings and interaction evidence as work proceeds, so an interrupted session can resume without inventing results.
Use the runtime's normal progress updates to explain what is covered, what remains, and any access or tooling limitations.

No scheduler, background agent, or provider-specific loop is required. If the user explicitly requests scheduled check-ins and the
runtime supports them, follow its scheduling and cleanup instructions. Scheduling does not authorize additional audit scope.

Resume from recorded evidence after an interruption, rechecking any state that may have changed. Completion depends on coverage and
the main skill's gates, not elapsed time or consecutive updates with no new findings.
